## 二、MemoryTool — 记忆工具

### 2.1 核心思想

把记忆从"内存"搬到"硬盘"。类比：

```
第7章：便利贴（夹在笔记本里，笔记本合上就丢）
第8章：笔记本（写在本子里，下次翻开还在）
```

### 2.2 数据流

```
save("用户叫张三，Python开发者")
  → 追加一条记录到 JSON 文件
  → {
      "content": "用户叫张三，Python开发者",
      "type": "semantic",
      "importance": 0.9,
      "created_at": "2026-07-07T..."
    }

search("张三 Python")
  → 读取 JSON 文件
  → 提取关键词：{"张三", "Python"}
  → 匹配每条记忆的关键词
  → 按匹配度 + importance 综合评分排序
  → 返回最相关的记忆
```

### 2.3 核心代码

```python
class MemoryTool:
    def __init__(self, file_path="memories.json"):
        self.file_path = file_path
        self._ensure_file()  # 文件不存在就创建空数组

    def save(self, content, memory_type="semantic", importance=0.5):
        # 1. 读 JSON → 2. 追加记录 → 3. 写回 JSON
        record = {"content": content, "type": memory_type, "importance": importance, ...}
        records = self._load_all()
        records.append(record)
        self._save_all(records)

    def search(self, query, limit=5):
        # 1. 提取查询关键词 → 2. 读取所有记忆
        # 3. 计算每条记忆的匹配分数
        # 4. 按分数排序返回
        query_keywords = self._extract_keywords(query)
        for r in records:
            overlap = query_keywords & r["keywords"]
            score = len(overlap) * importance_weight
            scored.append((score, r))
        return [r for _, r in sorted(scored)[:limit]]

    def _extract_keywords(self, text):
        """提取关键词（同时处理中英文）

        英文 → 按空格分词: "Python" → ["python"]
        中文 → 拆成单字:   "装饰器" → ["装", "饰", "器"]
        去掉停用词: "的", "了", "是", "the", "a" ...
        """
```

### 2.4 关键词搜索的挑战

| 语言 | 分词方式 | 例子 |
|------|---------|------|
| 英文 | 空格分词 | "Python developer" → ["python", "developer"] |
| 中文 | **单字拆分**（简化版） | "张三" → ["张", "三"] |
| 混合 | 分别处理 | "Python的装饰器" → ["python", "装", "饰", "器"] |

**为什么不用 jieba 分词？** 为了保持零依赖。以后升级可以换成 jieba 或向量搜索。

## 三、RAGTool — 检索增强生成

### 3.1 核心思想

**在问 LLM 之前，先查资料。**

```
普通 Prompt:
  问: "Python装饰器是什么？"
  LLM 凭训练数据回答

RAG Prompt:
  [资料] 装饰器是一种高级功能...
  问: "Python装饰器是什么？"
  LLM 基于资料回答 ← 更准确、可验证
```

### 3.2 RAG 的完整流程

```
                   知识文本
                      │
                      ▼
                ┌──────────────┐
                │  add_text()  │  → 分块、存储到 JSON
                └──────────────┘
                      │
                      ▼
  用户提问 ──→  ┌──────────────┐
                │  search()    │  → TF-IDF 关键词匹配
                └──────────────┘   → 找到最相关的 top_k 条
                      │
                      ▼
                ┌──────────────┐
                │build_context()│  → 拼成"根据资料回答"格式
                └──────────────┘
                      │
                      ▼
                ┌──────────────┐
                │  LLM 回答    │  → 基于资料 + 自身知识
                └──────────────┘
```

### 3.3 TF-IDF 风格的搜索

```
TF = 关键词在当前段落出现的次数
    （词频越高 → 越相关）

IDF = log(总段落数 / 包含该词的段落数)
    （"的"在很多段落出现 → IDF 低 → 权重低）
    （"装饰器"只在少数段落出现 → IDF 高 → 权重高）

最终分数 = sum(每个关键词的 TF × IDF)
```

这就是为什么"装饰器"的匹配权重比"是"、"的"高得多——**自动过滤掉常见词，突出关键词。**

### 3.4 文本分块

```python
def _chunk_text(self, text, chunk_size=200):
    # 按句号拆成句子
    sentences = re.split(r"(?<=[。！？.!?])\s*", text)
    # 把相邻句子拼成约 200 字的块
    chunks = []
    for s in sentences:
        if len(current) + len(s) < chunk_size:
            current += s
        else:
            chunks.append(current)
            current = s
```

## 六、关键知识点速查

### 记忆系统

- **持久化**：数据在内存中是临时的，写到文件才是永久的
- **检索**：搜索记忆 = 提取关键词 → 计算匹配度 → 排序返回
- **重要性加权**：`importance` 参数让重要记忆排名更靠前
- **记忆类型**：`working`（临时会话）和 `semantic`（长期知识）

### RAG 系统

- **RAG = 检索 + 增强 + 生成**：先查再答，不是直接问 LLM
- **分块**：长文本需要切碎（chunk），每块约 200 字
- **TF-IDF**：词频(TF) × 逆文档频率(IDF)，自动降权常见词
- **停用词**："的"、"了"、"是" 等无意义的词需要过滤
- **上下文注入**：把搜索结果以"资料N"格式拼进 prompt

### Python 技巧

- **`unicodedata.name(ch)`**：判断一个字符是不是中文（CJK 开头）
- **`json.load()` / `json.dump()`**：JSON 文件的读写
- **正则 `re.findall(r"[a-z0-9]+", text)`**：只提取英文字母和数字
- **集合运算 `&`**：求两个关键词集合的交集（共同关键词）
